# FPP Overlay Effects 1.0.1

**Fix: solid colors and other static looks now appear on FPP’s home/Status screen.**

Version 1.0.0 read FPP’s running-animation list, which omitted enabled solid fills and static Text/Image. This release uses the live overlay-enabled state instead. Anything applied by this plugin can appear: **solid colors, Text, Image, WLED animations, models, submodels, and groups**.

Each bubble shows **prop + look/effect + Stop**. Stop releases that target back to the show. **Stop shown** handles all displayed targets. When the last overlay stops or is disabled, the entire panel disappears. Radio and playlist controls are unaffected.

## Update an existing installation

1. Open **Content Setup → Plugin Manager / Plugins**.
2. Find **FPP Overlay Effects** and select **Update**.
3. Refresh the effect page and the normal FPP Status page. Use **Ctrl+F5** if an old page is cached.

**No reboot or FPPD restart is needed.** Already-active solid fills appear immediately, with the generic **Solid / static overlay** label when they predate this update. Their next Apply saves the exact look name and fill color.

## Use

Choose models, submodels, groups, or buffer views; select a solid color or effect; edit colors/options and press **Apply**. Enable Live changes and Apply once for subsequent completed edits to update output. Selection and preset loading never start lights. Open Status to see active-look bubbles and stop individual targets. Save named presets and favorites from the plugin page as before.

Successful commands save lightweight labels on the FPP. Labels do not claim lights are active: FPP’s live overlay state determines visibility. Failed commands, old presets, or stale labels cannot create inactive bubbles. If label storage fails, active overlays still appear and remain stoppable with a generic label.

## Validation and previews

Regression coverage includes solid Apply → Status navigation, static Text/Image, legacy fills with no label, failed commands, per-target Stop, mixed static/animated looks, stale history, and unavailable label storage. Tests use simulated FPP 10.4 responses. Physical-light validation is still needed on each installation.
